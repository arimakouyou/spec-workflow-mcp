# コードライター — GREEN フェーズ（サブエージェント）

このスキルは Agent ツール経由で**サブエージェント**として実行するよう設計されている。TDD の GREEN フェーズに従い、失敗テストをパスさせるために必要な最小限のプロダクションコードを記述する。

## 呼び出し元エージェントによる起動方法

```javascript
Agent({
  subagent_type: "general-purpose",
  description: "GREEN: テストをパスさせる実装",
  prompt: `あなたは TDD 実装者です。失敗テストをパスさせる最小限のコードを記述してください。

    Project path: {project-path}
    Spec name: {spec-name}
    Task ID: {task-id}
    Task prompt: {task _Prompt content}
    Test files: {test-file-paths}
    Leverage files: {_Leverage file paths}

    /spec-impl-code スキルの指示に従ってください。

    作成/変更したファイルのリストと実装アプローチを返してください。`
})
```

## GREEN フェーズのルール

1. **テストをパスさせる** — それが唯一の目標
2. **最小限のコードを書く** — テストを満たすために必要な分だけ（YAGNI）
3. **テストファイルを変更しない** — テストは仕様である
4. **テストされていない機能を追加しない** — テストがなければ作らない

## 実行ステップ

### 1. テストを読んで理解する

- 各テストファイルを読み、以下を理解する:
  - どのモジュール/関数がインポートされているか（これらを作成する必要がある）
  - どのインターフェースが期待されているか（パラメータ、戻り値の型）
  - どの動作が検証されているか（アサーションが契約を定義する）
  - どのエラー条件がテストされているか

### 2. 実装を計画する

テストから以下を導出する:
- どのファイルを作成する必要があるか
- どの関数/クラス/メソッドが必要か
- どの型/インターフェースが期待されているか
- 入力/出力の契約は何か

### 3. Green 戦略を選択する

`/tdd-skills` の Green 戦略に従う:

1. **Obvious Implementation**（解決策が明確な場合に推奨）: 実際のロジックを直接実装
2. **Fake It**（不確実な場合）: まず定数を返し、その後一般化
3. **Triangulation**（複数ケースがある場合）: 複数のテストアサーションから一般化

### 4. 実装する

- `_Leverage` ファイルを読んで既存のパターンとユーティリティを理解する
- コードベースの既存規約（命名、構造、エラーハンドリング）に従う
- テストがインポートするモジュールを作成する
- 期待されるシグネチャで関数/クラスを実装する
- エラーシナリオを含むすべてのテストケースに対応する

**重要な制約**: テストが要求するものだけを書く。テストが入力バリデーションをチェックしていなければ追加しない。テストがログ出力を検証していなければ追加しない。

### 5. ローカルでの確認（任意のクイックチェック）

可能であれば、以下を簡単にメンタルチェックする:
- インポートされるすべてのモジュールが存在するか
- 期待されるすべてのエクスポートが存在するか
- 関数シグネチャがテストの呼び出しと一致するか
- 戻り値の型がテストのアサーションと一致するか

## 出力フォーマット

呼び出し元エージェントに返す:

```
## GREEN フェーズ完了

### 作成したファイル
- {path/to/new-file-1}: {簡潔な説明}
- {path/to/new-file-2}: {簡潔な説明}

### 変更したファイル
- {path/to/existing-file}: {変更内容}

### 実装アプローチ
{アプローチと主要な判断を1-3文で説明}

### 使用した Green 戦略
{Obvious Implementation / Fake It / Triangulation} — {理由}
```
