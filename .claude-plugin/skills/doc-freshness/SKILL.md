# Document Freshness Management

Detect staleness of documents, rule files, and ADRs in the repository and prompt periodic review.

## Targets

- Document freshness check setup in weekly CI
- Manual periodic audits (90/120/180-day thresholds)
- Update decisions after stale document detection
- Additional judgment based on ADR status (`Proposed` / `Accepted` / `Deprecated` / `Superseded`)
- Drift detection between implementation and documentation at Phase Review (Expert Team Review)
- Integration with the `tech-debt` Skill (detecting neglected Open entries)

## Out of Scope

- Document writing style/structure -> each Skill / template
- Spec document consistency verification -> `spec-verify` / `spec-impact-analyze` Skill
- CI workflow setup -> `setup-ci` Skill

## Monitoring Targets

| Document type | Path | Threshold | Action |
|---------------|------|-----------|--------|
| Rule files | `.claude-plugin/rules/*.md` | 90 days | Review whether content matches the current state |
| ADR | `.claude/_docs/adr/*.md` | 180 days | Confirm whether status remains Accepted |
| Steering docs | `.spec-workflow/steering/*.md` | 90 days | Reflect changes to tech stack and policy |
| Design docs | `.spec-workflow/specs/*/design.md` | 120 days | Confirm there is no drift from implementation |
| Tech debt | `.claude/_docs/tech-debt/*.md` | 90 days | Review whether Open entries have been left unattended |
| Know-how | `.claude/_docs/know-how/**/*.md` | 180 days | Review whether content matches the current codebase |

## Detection Method

### Git-based Last-Modified Detection

```bash
# Get the file's last modification date (git log based)
git log -1 --format="%ci" -- "$FILE_PATH"

# Compute elapsed days
LAST_MOD=$(git log -1 --format="%at" -- "$FILE_PATH")
NOW=$(date +%s)
AGE_DAYS=$(( (NOW - LAST_MOD) / 86400 ))
```

### Threshold Judgment

| Elapsed days | Status | Response |
|--------------|--------|----------|
| 0-60 days | Fresh | No action required |
| 61-90 days | Warning | Review recommended |
| 91 days or more | Stale | Review required; Issue creation target |

## CI Integration

The weekly CI workflow generated by `/setup-ci --with-scheduled` includes:

1. **Document freshness check**: Scans the last-modified date of all monitored files
2. **Issue creation**: Automatically creates a GitHub Issue when stale files are detected
3. **Labels**: Adds `quality` and `automated` labels

## ADR-specific Freshness Management

ADRs receive additional judgment based on the status field:

| status | Threshold judgment |
|--------|--------------------|
| Proposed | Warning if not transitioned to Accepted / Rejected within 30 days |
| Accepted | Apply the standard 180-day threshold |
| Deprecated | Excluded from freshness check |
| Superseded | Excluded from freshness check (refer to successor ADR) |

## Integration with review-worker

At Phase Review (step 3.5.2 Expert Team Review), the quality / maintainability reviewer confirms:

- Whether documents related to the changed modules have become Stale
- Whether the implementation has drifted from the documentation
- If drift exists, report a documentation update as a finding

## Manual Check

Even without periodic CI, manual checks are possible with the following command:

```bash
# Detect rule files not updated for 90+ days
for f in .claude-plugin/rules/*.md; do
  age=$(( ($(date +%s) - $(git log -1 --format="%at" -- "$f")) / 86400 ))
  [ "$age" -gt 90 ] && echo "STALE ($age days): $f"
done
```
