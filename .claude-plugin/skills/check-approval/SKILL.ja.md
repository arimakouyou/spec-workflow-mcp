# 承認ステータスの確認

保留中の承認のステータスを確認し、結果に応じて適切なアクションを実行する。このスキルはスペックワークフロー中に `/loop` から繰り返し呼び出されるよう設計されている。

## 使い方

承認ワークフロー中に `/loop` から自動的に呼び出される:
```
/loop 1m /check-approval <approvalId>
```

## プロセス

### 1. ステータスの確認

`approvals` MCP ツールを呼び出す:
```
approvals action: 'status', approvalId: '<approvalId>'
```

### 2. 結果の処理

#### `pending` の場合:
報告: 「承認はまだ保留中です。ダッシュボード/VS Code 拡張機能でのレビューを待機しています...」
ループは次のインターバルでこのスキルを再度呼び出す。

#### `approved` の場合:
1. 報告: 「承認されました！」
2. **直ちにクリーンアップを実行**: `approvals action:"delete" approvalId:"<approvalId>"`
   - 削除が失敗した場合: エラーを報告し、次のループ反復でリトライ
   - 削除が成功した場合: 「クリーンアップ完了。」と報告
3. **ループを停止** — ユーザーに伝える: 「承認が完了しクリーンアップされました。次のフェーズに進みます。」
4. 呼び出し元のスキルの自動遷移が次のフェーズへの進行を処理する。

#### `needs-revision` の場合:
1. **ループを停止する。**
2. 承認レスポンスからレビュアーのコメントを報告する。
3. ユーザーに伝える: 「修正が要求されました。上記のコメントを確認してください。」
4. 呼び出し元のスキルはレビューコメントに基づいてドキュメントを更新し、セルフレビューを再実行し、新しい `/loop` で新しい承認リクエストを送信すべきである。

#### `rejected` の場合:
1. **ループを停止する。**
2. 拒否理由を報告する。
3. ユーザーに伝える: 「承認が拒否されました。フィードバックを確認してください。」

## ルール

- このスキルはステータスの確認とクリーンアップのみを行う — スペックドキュメントは変更しない
- 口頭での承認は**決して**受け入れない — ダッシュボード/VS Code 拡張機能での承認のみが有効
- ワークフローが進行する前に `approvals action:'delete'` が成功しなければならない
- 削除が失敗した場合は進行せず、次のループ反復でリトライする
