# ナレッジキャプチャ

ユーザーとのやり取りで得た実践的なチームナレッジを `.claude/_docs/know-how/` に蓄積し、
将来のタスクで同じミスを繰り返さないようにするスキル。

個人的な好みや作業スタイルは、ここではなく組み込みメモリシステムに記録すべきである。

## 2つの記録パターン

### パターン A: 明示的な記録（ユーザー指示型）

ユーザーが「覚えておいて」「ナレッジに追加」「今後はこうして」と言った場合。
確認なしで即座に記録する。

**トリガー例:**
- 「覚えておいて」
- 「ナレッジに追加して」
- 「今後はこうしてね」
- 「remember this」

**動作:** ナレッジファイルを即座に作成し、INDEX.md を更新する。

### パターン B: 提案型記録（検出 + 確認）

AI がユーザーの修正指示や指示を検出し、「ナレッジとして記録しますか?」と提案する。
ユーザーが承認した場合のみ記録する。

**トリガー条件:**
- ユーザーが AI の出力や判断を明確に修正した（「それは違う、こうだよ」「いや、これは...」）
- ユーザーが AI のアプローチを拒否し、別の方法を指示した
- ユーザーがプロジェクト固有の規約やルールを共有した
- 同じセッション内で同種の修正が2回以上あった

**動作:**
1. 修正内容を要約して提示する
2. 「このナレッジをナレッジとして記録しますか?」と確認する
3. ユーザーが承認したら記録する

**提案フォーマット:**

```
[ナレッジ提案] 以下のナレッジを記録できます:
- 要約: {修正内容の1行要約}
- ドメイン: {testing / workflow / conventions / ...}
ナレッジに追加しますか?
```

## ステップバイステップ記録手順

### ステップ 1: ドメインの決定

ナレッジの内容に基づいてドメインを選択する。

| ドメイン | 内容 |
|--------|---------|
| testing | テスト設計、構造、実行に関するナレッジ |
| workflow | 開発フロー、Git 操作、CI/CD に関するナレッジ |
| conventions | 命名規則、ディレクトリ構造、コードスタイル |
| architecture | レイヤー構造、DI、設計上の意思決定 |
| debugging | デバッグ手法、エラーハンドリング、パフォーマンス |

既存のドメインに当てはまらない場合は、新しいドメインを作成してもよい。

### ステップ 2: 重複チェック

`.claude/_docs/know-how/INDEX.md` を読み、同じナレッジが既に存在しないことを確認する。
重複がある場合は、新規作成ではなく既存ファイルを更新する。

### ステップ 3: ファイルの作成

以下のフォーマットで `.claude/_docs/know-how/{domain}/{slug}.md` を作成する:

```markdown
---
created: {YYYY-MM-DD}
domain: {domain}
source: user-feedback
---

# {タイトル（簡潔に）}

## 要約

{ナレッジの核心を1-2文で記述}

## 背景

{なぜこのナレッジが必要か、どのような状況で生まれたか}

## チェックリスト

- [ ] {実装時に確認すべき項目 1}
- [ ] {実装時に確認すべき項目 2}

## 反例

{このナレッジを無視した場合に何が起こるか}
```

**制約:**
- 50行以内を目標とする（長い場合は分割を検討）
- フロントマターの `created`、`domain`、`source` フィールドは必須

### ステップ 4: INDEX.md の更新

`.claude/_docs/know-how/INDEX.md` の該当ドメインテーブルに1行追加する。
ドメインセクションが存在しない場合は、新しいセクションを追加する。

## パターン判定フローチャート

```
ユーザーの発言を検出
  │
  ├─ 「覚えておいて」「remember」等の明示的な指示？
  │   └─ YES → パターン A（即座に記録）
  │
  ├─ ユーザーが AI の判断を修正または拒否した？
  │   └─ YES → パターン B（提案して確認）
  │
  ├─ ユーザーがプロジェクト固有の規約を共有した？
  │   └─ YES → パターン B（提案して確認）
  │
  └─ 同種の修正が2回以上あった？
      └─ YES → パターン B（提案して確認）
```

## 注意事項

- **メモリとの区別**: 「チームメンバーも知るべきか?」→ はい = ナレッジ、いいえ = 組み込みメモリ
- 一時的な状態（現在のブランチ名、進行中のタスク等）をナレッジに書かない
- ナレッジは「実践的な知識」のためのもの。確立されたルールは `.claude/rules/` に昇格させるべき
- ユーザーが「ルールにして」と言った場合、ナレッジを `.claude/rules/` のルールに昇格させる
- ファイル作成後のステージングとコミットは、ユーザーが明示的に要求した場合のみ行う
