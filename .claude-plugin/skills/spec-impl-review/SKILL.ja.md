# コードレビュアー — REFACTOR フェーズ（サブエージェント）

このスキルは Agent ツール経由で**サブエージェント**として実行するよう設計されている。TDD の REFACTOR フェーズに従い、テストコードとプロダクションコードの両方をレビュー・リファクタリングする。

## 呼び出し元エージェントによる起動方法

```javascript
Agent({
  subagent_type: "general-purpose",
  description: "REFACTOR: レビューとクリーンアップ",
  prompt: `あなたは TDD リファクタリングレビュアーです。RED-GREEN フェーズで書かれたコードをレビュー・リファクタリングしてください。

    Project path: {project-path}
    Spec name: {spec-name}
    Task ID: {task-id}
    Task prompt: {task _Prompt content}
    Test files: {test-file-paths}
    Implementation files: {implementation-file-paths}
    Success criteria: {success criteria from _Prompt}

    /spec-impl-review スキルの指示に従ってください。

    変更のリストと品質評価を返してください。`
})
```

## REFACTOR フェーズのルール

1. **テストの期待値を変更しない** — アサーションと期待値はそのまま維持
2. **新機能を追加しない** — リファクタリングは構造を変え、動作は変えない
3. **変更のたびにテストがパスし続けること** — 小さく安全なステップでリファクタリング
4. **明瞭性と保守性を向上させる** — きれいで読みやすいコードが目標

## 実行ステップ

### 1. すべてのコードを読む

テストファイルと実装ファイルの両方を読み、以下を理解する:
- 何が構築されたかの全体像
- テストとプロダクションコードの関係
- 現在のコード品質と構造

### 2. 成功基準のチェック

タスクの `_Prompt` の Success 基準と照合する:
- すべての成功基準が実装によって対処されているか？
- 要求されたものと構築されたものの間にギャップはないか？
- 未達の基準をフラグする（ただし修正のためにテストされていない機能を追加しない）

### 3. 設計原則を適用する

設計ガイダンスについて `/tdd-skills` と `tdd-skills/references/tdd-and-design.md` を参照する:

**プロダクションコードのリファクタリング:**
- **重複**: 共有ロジックをヘルパー関数に抽出
- **命名**: 変数、関数、クラス名をより明確に改善
- **責務**: 多すぎる処理を持つ関数/クラスを分割（SRP）
- **エラーハンドリング**: 一貫した適切なエラーハンドリングを確保
- **型安全性**: 型を厳密化し、可能な限り `any` を除去
- **コード構成**: インポート、順序、グルーピングの改善

**テストコードのリファクタリング:**
- **可読性**: テスト名の改善、describe ブロックでのグルーピング
- **DRY セットアップ**: 繰り返しのセットアップを `beforeEach` / フィクスチャに抽出
- **アサーションの明確さ**: より具体的なマッチャーを使用
- **テストの独立性**: テスト間で共有される可変状態がないことを確認

### 4. リファクタリングの実行

小さくインクリメンタルなステップで変更する。各変更について:
- コード品質の明確な改善であること
- 観測可能な動作を変更しないこと
- テストの期待値を変更したり新しいアサーションを追加しないこと

### 5. 品質評価

最終コードを以下の観点で評価する:
- **正確性**: タスクの要件を満たしているか？
- **可読性**: コードは理解しやすいか？
- **保守性**: 将来の変更が容易か？
- **テストカバレッジ**: テストが動作を十分にカバーしているか？
- **一貫性**: 既存のコードベースパターンに従っているか？

