# テストパターン

## テストフィクスチャ

テストの共有セットアップ。フレームワークのフィクスチャ機構（例: `@pytest.fixture`、`beforeEach`、`@BeforeEach`）を使って共通テストデータを作成する。

## テストデータビルダー

合理的なデフォルト値を持つ複雑なオブジェクトを流暢に構築する。各テストに関連するフィールドのみを指定する。

```
builder = UserBuilder().with_name("Alice").with_role("admin").build()
```

利点:
- テストが重要なことを強調し、重要でないことを隠す
- バリエーションの作成が容易
- デフォルト値の集中管理

## パラメータ化テスト

同じテストロジックを複数の入力で実行する。フレームワークのパラメータ化サポート（例: `@pytest.mark.parametrize`、`test.each`、`@ParameterizedTest`）を使用する。

最適な用途: 境界値、同値クラス、真理値表。

## 1テスト1コンセプト

各テストは1つの論理的コンセプトを検証すべき。すべてが同じコンセプトを検証するなら、複数のアサーションは問題ない。

**悪い例**: 作成、更新、削除を1つのテストでチェック。
**良い例**: 各操作ごとに個別のテスト。

**例外**: 1つのコンセプトを検証する複数のアサーション（例: 単一の API 呼び出しのステータスコードとレスポンスボディの両方をチェック）は1つのテストで問題ない。

## まとめ

- 共有セットアップにフィクスチャ
- 柔軟なテストデータにビルダーパターン
- 重複削減にパラメータ化
- 1テスト1コンセプト
