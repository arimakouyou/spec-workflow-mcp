# テストダブル

外部依存を分離して、テストを高速かつ決定的にする。

## 5つのタイプ

### 1. Dummy
必要なパラメータを埋めるが、実際には使用されない。

### 2. Stub
固定値を返す。依存関係が返すものを制御する必要がある場合に使用。

用途: DB 結果、API レスポンス、設定値。

### 3. Spy
後で検証するために呼び出しを記録する。何かが起こったこと（例: メール送信、イベント発行）を確認する必要がある場合に使用。

### 4. Mock
期待を事前に設定し、インタラクションを検証する。呼び出し検証がテストのポイントである場合に使用。

**Mock vs Spy**: Mock は動作の期待を検証する。Spy は記録し、後でアサートする。

### 5. Fake
軽量な動作する実装（例: インメモリリポジトリ）。Stub では単純すぎる複雑な状態の相互作用に使用。

## 選択ガイド

```
何をテストしている？
  ├─ 戻り値のみ            → Stub
  ├─ 呼ばれたか？          → Mock
  ├─ 呼び出し履歴/詳細     → Spy
  ├─ 複雑な状態遷移        → Fake
  └─ 未使用パラメータ      → Dummy
```

| シナリオ | 推奨 | 理由 |
|---------|------|------|
| 外部 API 呼び出し | Stub / Mock | 固定レスポンス、呼び出し検証 |
| データベースアクセス | Fake / Stub | 速度、状態管理 |
| 副作用（メール、ログ） | Spy / Mock | 発生の検証 |
| ランダム値 / 時刻 | Stub | 決定的な結果 |
| 複雑なビジネスロジック | Fake | 現実的な動作 |

## アンチパターン: 過度なモック化

すべてがモックだと、テストは何も有意義なことを検証しない。テスト対象のコードには実オブジェクトを使い、外部境界（I/O、ネットワーク、時刻）のみをモックする。

> 「Mock より Stub を好め。状態の検証は動作の検証に優る。」— Martin Fowler

## 原則

**動作する最もシンプルなテストダブルを使う。迷ったら Stub から始める。**
