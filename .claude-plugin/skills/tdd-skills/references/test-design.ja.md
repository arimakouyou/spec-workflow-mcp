# テスト設計

## 境界値分析

バグは境界周辺に集中する。各境界の値とその周辺を常にテストする。

例 — 年齢カテゴリ（0-17: 未成年、18-64: 成人、65+: 高齢者）:
- 17、18 をテスト（未成年/成人の境界）
- 64、65 をテスト（成人/高齢者の境界）

## 同値分割

同じ動作を生成する入力をグループ化し、各グループから1つの代表値とすべての境界値をテストする。

例 — 割引ティア（0-999: 0%、1000-4999: 5%、5000+: 10%）:
- 代表値: 500、3000、10000
- 境界値: 999、1000、4999、5000

## テスト命名

テストの目的が名前から明確になる一貫したパターンを使用する:

| パターン | 例 |
|---------|---|
| `test_{subject}_{condition}_{expected}` | `test_total_when_cart_empty_returns_zero` |
| `test_{action}_raises_{error}_when_{condition}` | `test_add_item_raises_error_when_negative_price` |

テストが失敗したときに何が問題だったかを名前が説明すべき。

## エラー / 例外テスト

ハッピーパスだけでなく、常にエラーパスをテストする:
- 無効な入力
- 境界違反
- リソースの利用不可
- エラーの型とエラーメッセージの内容の両方を検証

## まとめ

- 常に境界値をテスト
- 効率のために同値分割を使用
- 明確で説明的な命名
- エラーケースを忘れない
