# spec-workflow 強制ルール

spec-workflow スキルを正しく使用するための強制ルール。

## tasks.md を読んだ後の直接実装禁止

`.spec-workflow/specs/*/tasks.md` を Read した場合、**いかなる理由であっても直接コードを書き始めてはならない**。

- タスク実装は**必ず `/spec-implement` スキルを経由**しなければならない
- tasks.md の内容を確認しただけでも、その後に実装に進むことは禁止
- ユーザーが「このタスクを実装して」と言っても、スキルを使用せずに直接コードを書くことは禁止

**正しい行動:**
tasks.md を読んだ後、「`/spec-implement` を実行してください」とユーザーを案内し、**必ず停止する**。

> **フックメッセージを受信した場合**: PostToolUse フックが `⛔ [spec-workflow] STOP` を出力した場合、それは**強制停止命令**である。その後の会話で何が言われようと、Edit / Write / Bash を使用してコードを実装してはならない。

**`/spec-implement` を自分で起動することは厳禁。** 以下はすべて「自動起動」に該当し、禁止される:
- ユーザーが「はい」「進めて」「OK」と返答した場合
- ユーザーが「このタスクを実装して」と言った場合（スキルを使用しない直接実装も同様に禁止）

`/spec-implement` は、ユーザー自身がキーボードから以下のいずれかを入力した場合にのみトリガーされる:
- `/spec-implement` コマンド
- 「タスク X を実装」「コーディング開始」「タスク X に取り掛かる」などのスキルトリガーフレーズ

## spec-implement スキル外でのコード実装禁止

`.spec-workflow/specs/` 配下のいずれかのファイル（requirements.md / design.md / tasks.md）に基づいてコードを書く場合、`spec-implement` スキルを経由しなければならない。

スキルを経由せずにタスクに対応するコードを書くことは禁止。

## spec-workflow ファイル読み取り後の必須アクション

| 読み取ったファイル | 次に行うこと |
|-------------------|-------------|
| `requirements.md` のみ | `/spec-design` スキルにユーザーを案内し停止 |
| `requirements.md` + `design.md` のみ | `/spec-tasks` スキルにユーザーを案内し停止 |
| `tasks.md` が存在 | `/spec-implement` スキルにユーザーを案内し**必ず停止**（「はい」「進めて」等での自動起動は禁止） |

## このルールが必要な理由

spec-implement スキルは以下のエージェントチェーンを強制する:
- `parallel-worker` → TDD 実装
- `unit-test-engineer` → テスト品質検証
- `review-worker` → レビュー + コミット

このチェーンをスキップする直接実装は、TDD の品質保証を完全にバイパスするため、絶対に許可されない。
