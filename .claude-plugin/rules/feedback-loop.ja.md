# フィードバックループ

## 組み込みメモリとの区別

- **know-how**（`.claude/_docs/know-how/`）: プロジェクト固有の実践的知識。Git 管理下に置き、チームで共有する。技術的決定、落とし穴、ベストプラクティスなど。
- **組み込みメモリ**（`~/.claude/projects/.../memory/`）: 個人の好みや作業スタイル。Git 管理下に置かない。

迷った場合は「チームメンバーがこれを知るべきか？」と問う。はい → know-how、いいえ → メモリ。

## タスク開始時の参照

タスクを開始する前に `.claude/_docs/know-how/INDEX.md` を確認し、関連する know-how がある場合は対応するファイルを Read する。

参照フロー:
1. INDEX.md のドメイン一覧を確認する
2. タスクのキーワード（例: "testing"、"migration"、"cache"）に一致するドメインを特定する
3. 関連する know-how の「チェックリスト」と「アンチパターン」を実装判断に反映する

INDEX.md が空、または一致するドメインが存在しない場合はこのステップをスキップしてよい。

## フィードバックの検出と記録

以下のいずれかを検出した場合、`/knowhow-capture` スキルを使用して know-how を記録する:

- ユーザーが「これを覚えて」「次回から〜して」のような発言をした → スキルパターン A（即座に記録）
- ユーザーが AI の判断を修正・否定した → スキルパターン B（提案型）
- 同じフィードバックを2回以上受けた → スキルパターン B（提案型）

記録手順、フォーマット、ルールへの昇格については `/knowhow-capture` スキルに従うこと。
